# Camera Controls and UI

## Objective
Make camera selection and frame-rate control clear and usable in GreenCam without changing its USB/OBS transport.

## Problem and scope
The app already toggles front/back cameras, but does not show the active camera. Its output frame pacing is hard-coded to 15 FPS. Add explicit front/rear selection, live 10/15/30/60 FPS output caps, and a clearer foreground control layout. Camera hardware may deliver fewer frames than the selected cap; do not promise an exact capture rate. A 60 FPS selection changes only output pacing; it does not request a CameraX source rate. Additional physical rear lenses, audio, background capture, and network streaming are out of scope.

## Acceptance criteria
- User can see and choose the available front/rear camera and change it while running.
- User can choose an output cap of 10, 15, 30, or 60 FPS while running; default remains 15. The UI and README say "up to" rather than guaranteeing camera hardware rate. Selecting 60 changes only output pacing; it does not request a 60 FPS CameraX source mode.
- Preview, USB stream, permission, stop/restart, and unavailable-camera behavior remain functional.
- Unit tests cover supported caps and pacing, including 60 FPS; APK build and lint pass; feasible device/OBS smoke checks have observed outcomes or are explicitly pending.
